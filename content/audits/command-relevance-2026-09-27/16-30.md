# Command relevance review: chapters 16–30

Reviewed 27 September 2026. This review selects what deserves command practice before adding feedback. It supersedes the prior command trainer's assumption that every existing exercise should remain. The [decision ledger](16-30.json) accounts for every original identity and each new one.

The result is **109 exercises from 150 previously**: 106 revised, 44 retired and 3 added. All retained exercises use one optional conceptual hint and one short post-answer takeaway. Their task includes the indispensable device, interface, mode or platform context. The repeated purpose/preparation/verification sections and notes were removed from these banks.

The bank is deliberately uneven. Routing-table and FHRP competence comes primarily from interpreting evidence. Configuration chapters need more distinct decisions. Chapter 30 legitimately needs platform alternatives because the course covers three client operating systems; it does not require three physical installations.

## Scope and sources

The [course practice plan](../../PRACTICE-PLAN.md), [09–23 implementation report](../practice-09-23/README.md), [24–33 implementation report](../practice-24-33/README.md), each chapter's relevant lesson sections, and its guided/independent lab outcomes informed selection. These documents distinguish supplied preparation from independent assessment.

Both [Cisco v1.1](https://learningcontent.cisco.com/documents/marketing/exam-topics/200-301-CCNA-v1.1.pdf) and [Cisco v2.0](https://learningcontent.cisco.com/documents/marketing/exam-topics/200-301_CCNA_v2.0_Exam_Topics_PDF.pdf) were checked on the review date. Track-specific decisions follow the verbs: FHRP interpretation does not require a CLI memorization bank; v1 QoS explanation does not require MQC; DNS diagnosis does not require eight IOS resolver setup commands. OSPFv3, server-side DHCP troubleshooting, secure transfers, storm control and RA guard receive their stated v2 depth. NTP's configuration requirement belongs to v1. Counts and difficulty assignments are course-design judgments, not Cisco-prescribed quotas.

New syntax and selected query decisions were checked against primary references:

- [Cisco DHCP/snooping configuration](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst9300/software/release/17-12/configuration_guide/ip/b_1712_ip_9300_cg/configuring_dhcp.html): global enablement, VLAN selection and binding evidence are different operations.
- [Cisco IPv6 First Hop Security](https://www.cisco.com/c/en/us/td/docs/switches/lan/catalyst9300/software/release/17-12/configuration_guide/sec/b_1712_sec_9300_cg/configuring_ipv6_first_hop_security.html): `device-role host` in RA-guard policy context, policy attachment and the separate authorized-router boundary.
- [Apple's ifconfig manual source](https://github.com/apple-oss-distributions/network_cmds/blob/main/ifconfig.tproj/ifconfig.8): inspect the named macOS interface, with its actual address/netmask/state.
- [Microsoft nslookup reference](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/nslookup): explicit server selection and record-type queries.

Retained command spellings were previously checked against the technical references documented in the [foundations/routing audit](../command-trainer-2026-09-27/foundations-routing.md) and [services audit](../command-trainer-2026-09-27/services-security-automation.md). Their earlier retention decisions are superseded here; their platform references remain useful. No production network, Packet Tracer topology, IOS image or native OS command was executed during this content selection pass.
