# Foundations, switching and routing command audit

Reviewed 27 September 2026. This report covers the 218 command drills in chapters 00–23. Chapters 00–17 were authored by the foundations/switching reviewer; the matcher reviewer independently completed chapters 18–23 after finishing the matching work. The parent audit integrates this range with the later chapters and the trainer interface.

Every drill now explains its purpose, the state and command mode required before attempting it, the role of each syntax component, the evidence to inspect afterward, and its teaching focus. Each lesson reference resolves to an existing section in the same chapter. Syntax parts reconstruct the canonical answer exactly when joined with single spaces. Configured names, secrets, addresses, masks, process IDs, values and filter expressions are arguments; interface identifiers have their own type. A `show` drill's verification entry identifies the output being interpreted rather than asking the learner to run an identical command again without a reason.

No drills were removed or added. All 218 original IDs, order, tasks, prompts, answers, accepted alternatives and notes were preserved. The changes in this range add teaching context and track-specific focus metadata. No lesson, lab, question, card, application, style or matcher file was edited by this content assignment.

## Scope and progression

The current [CCNA v1.1 objectives](https://learningcontent.cisco.com/documents/marketing/exam-topics/200-301-CCNA-v1.1.pdf) and announced [CCNA v2.0 objectives](https://learningcontent.cisco.com/documents/marketing/exam-topics/200-301_CCNA_v2.0_Exam_Topics_PDF.pdf) informed the distinction between core and supporting practice. These are teaching labels, not predictions that an exact command will appear on an exam. Basic mode navigation remains core because it is a prerequisite for the configuration skills. Optional inspection utilities, legacy encapsulation selection, static MAC experiments and timed recovery policy remain supporting depth.

The track overrides matter where the objective changes substantially: STP configuration, PoE configuration/operational checks, storm control, RA guard, OSPFv3 and FHRP status interpretation. The relevant drills identify supporting depth for v1.1 and core practice for v2.0. Their expected behavior is not changed by the selected track. Current versus announced scope follows [Cisco's transition notice](https://blogs.cisco.com/learning/stay-on-track-get-certified-before-the-ccna-refresh); the published objectives remain subject to Cisco's updates.

The review checked each original command against its chapter's lesson and lab context, including available interfaces, independent variations, setup prerequisites, accepted platform forms and the limits of the proposed verification. Existing safe distinctions were retained rather than rewritten solely for style. The principal gaps were missing starting context and insufficient explanation of what output establishes, not invalid command answers.

## Verification and limits

The range-specific structural check passed for all 218 drills: 413 syntax components reproduce their answers exactly; 224 verification entries are present; every lesson anchor resolves; required explanation fields are populated; and checked literal values are not mislabeled as keywords. There are 190 default core and 28 default supporting labels, with 32 track overrides. These counts describe the saved authoring state, not an exam coverage percentage.

The original non-teaching fields in all 218 records also match Git HEAD exactly, confirming that this authoring pass preserved the existing commands and their identities. Teaching explanations range from 86 to 141 words, averaging 114; length was not used as an item quota. All 25 relative report links resolve. Content validation completed with zero errors and the existing ten objective-tag warnings.

The matcher reviewer reported 24 passing command-matcher tests against the complete 366-command bank and 61 accepted variants, including literal, interface and whitespace regressions. The parent [command-trainer audit](README.md) records final integrated application and browser verification; this range report does not substitute a content structure check for those results.

This was a documentation, lesson/lab-context and authored-data review. No Packet Tracer, CML, physical-switch or router execution was performed. Expected output describes what to check under the stated conditions, not a recorded device run. Existing progress identities remain stable, and no pass guarantee, deployment, commit or push is implied by this audit.
